operator[] Cluster: element access — 1 operator, 2 uses (read and write)

Source: vect2 main, lines: v1[0], v1[1], v1[1] = 12;, v3[1].

The mechanism: operator[] is a member function

x[i] is defined by the compiler to mean x.operator[](i). It must be a member function — C++ does not allow a free-function form of operator[].

Slot: declaration, inside the class int& operator[](int index); Rule: return type int& (a reference to int, not a plain int) is what makes v1[1] = 12; valid. v1[1] evaluates to a reference to the actual stored int inside v1 — assigning to that reference writes through to the object. If the return type were plain int (a copy), v1[1] = 12; would still compile but would assign into a temporary copy and change nothing inside v1.
Contrast: v3[1] on a const object v3 is declared const vect2 v3(v2);. Calling v3[1] requires a second overload: int operator[](int index) const; — the trailing const after the parameter list marks this version as usable on a const object, and it must return by value or by const reference, never a plain non-const reference (a const object cannot expose a way to be modified). You need both overloads: one non-const (read/write), one const (read-only), same name, same parameter list, distinguished only by the trailing const.

What you write

In vect2/vect2.hpp: declare both overloads of operator[]. In vect2/vect2.cpp: implement both. Recompile against vect2/main.cpp through the lines using v1[0], v1[1], v1[1] = 12;, v3[1].

Primary source
cppreference — Operator overloading, section "Array subscript operator". Ignore every other operator listed on that page for now.

Ask directly if the reference-return rule is unclear before moving on — this rule reappears for every operator that needs to support chained assignment.
