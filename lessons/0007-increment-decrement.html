++ and --, prefix vs. postfix Cluster: 2 tokens, 4 overloads, 1 signature trick to tell them apart

Source: vect2 main — v4++, ++v4, v4--, --v4, with the expected values showing the difference: 

v4++  // prints 2,3 (the value BEFORE incrementing)
++v4  // prints 3,4 (the value AFTER incrementing)

Prefix: value after the change

Slot: declaration, inside the class, no parameters vect2& operator++(); Rule: modifies the object in place, then returns a reference to itself (same reasoning as lesson 6's +=) — the returned value reflects the state after modification.

Postfix: value before the change

Contrast: same name, ++ has no way to write "prefix" or "postfix" in the signature C++ has no keyword for this distinction. The chosen convention is: postfix takes one int parameter that is never used for anything — its only job is to make the parameter list different from prefix's, so the compiler can tell the two overloads apart. Calling v4++ passes 0 for that parameter automatically; you never supply it yourself.
Slot: declaration, inside the class, one unused int parameter vect2 operator++(int); Rule: before modifying, save a copy of the current state (vect2 before = *this;), modify *this the same way prefix does, then return before; — by value, not by reference, since before is a local variable that stops existing once the function returns; returning a reference to it would refer to destroyed memory.

Same two-overload pattern for operator--() / operator--(int).

What you write

Add all four: operator++(), operator++(int), operator--(), operator--(int). Recompile through the four increment/decrement lines and check the printed values match the comments exactly (this is where prefix/postfix mistakes show up immediately).
