const, three positions Cluster: one keyword, three unrelated rules depending on where it sits

You have already written all three without a name for them (lessons 1, 2, 4). This lesson names each one so the rule is explicit instead of copied by pattern-matching.

Position 1 — on a variable declaration

Slot: const Type name(...); const vect2 v3(v2); Rule: v3 cannot be reassigned, and no non-const member function can be called on it (only functions marked const, position 3 below, are callable on it). This is enforced at compile time, not runtime.

Position 2 — on a reference parameter

Slot: (const Type& name) operator+(const vect2& other) Rule: other is a reference (no copy made — cheaper for anything larger than a couple of ints) but the function promises not to modify what other refers to. Without const here, the function could not accept a const vect2 argument, and a + b in bigint's main would fail to compile since a is declared const bigint a(42);.

Position 3 — on a member function, after the parameter list

Slot: ReturnType name(...) const; int operator[](int index) const; Rule: promises this function does not modify the object it is called on (*this is treated as const inside the function body). This is the only thing that makes it legal to call the function on a const object — a non-const member function cannot be called on a const object at all, regardless of what the function body actually does.
Contrast: all three read left-to-right differently const vect2& x — const binds to what's on its immediate right (vect2): "reference to a const vect2." int foo() const; — const after the closing parenthesis binds to the function itself, not to the return type or any parameter: "this function does not modify the object." Same keyword, position determines which of two unrelated things it restricts — the object being referred to, or the function's permission to modify.

What you check

Re-read every function you wrote in lessons 1–8. For each: does it modify the object's own components? If no, it is missing const at position 3 unless already present. Does it take another vect2 as a parameter? If yes, that parameter should be const vect2& unless you have a specific reason it needs to modify the argument (none of vect2's operators do).
