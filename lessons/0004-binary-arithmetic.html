Binary arithmetic: +, -, * by scalar Cluster: producing a new object from two operands — member is enough until operand order flips

Source: vect2 main — a + b, v3 + v3 * 2, 3 * v2, v1 - v1 + v1. bigint main has the same shape for a + b.

The default: member function is enough

Slot: declaration, inside the class vect2 operator+(const vect2& other) const; Rule: the left operand (v3 in v3 + v3) is the object the function is called on implicitly; the right operand is the explicit parameter. Trailing const means this function does not modify the object it's called on — required here since a in bigint's main is itself declared const bigint a(42); and still needs to support a + b. Return type is a new vect2 by value (not a reference) — the result is a freshly computed object, nothing existing to refer back to.

The same slot and rule apply to operator- (v1 - v1 + v1) and to operator* when the scalar is on the right: v3 * 2 becomes v3.operator*(2) — 2 converts to the parameter's declared type (int), no extra work needed.

Contrast: 3 * v2 — scalar on the left 3 * v2 would desugar to 3.operator*(v2) if * had to be a member function — but 3 is a plain int, which has no member functions at all. A member operator* only fires when your class is the left operand. When the left operand is a built-in type, the only option is the same fix as lesson 3's operator<<: a free function.
Slot: free function, not inside the class vect2 operator*(int scalar, const vect2& v); Rule: both operands are explicit parameters, in left-to-right order matching the expression 3 * v2. Implement it by calling the member version you already have (return v * scalar;) — no new arithmetic logic, just a second entry point for the reversed operand order.

What you write

In vect2/vect2.hpp/.cpp: member operator+, member operator-, member operator*(int), and the one free function operator*(int, const vect2&). Recompile through v3 + v3 * 2, 3 * v2, v1 - v1 + v1.
