operator<<, stream-insertion form Cluster: printing an object — 1 rule, applies identically to vect2 and bigint

Source: vect2 main, std::cout << v1 << std::endl;. Same shape in bigint main: std::cout << "a = " << a << std::endl;.

Why this cannot be a member function

For a member function, the object to the left of the dot (the one that would receive the call, e.g. a.operator<<(...)) is the left-hand operand. But in std::cout << a, the left-hand operand is std::cout, an std::ostream — a type you did not write and cannot add a member function to.

Slot: free function, not inside the class std::ostream& operator<<(std::ostream& os, const vect2& v); Rule: this is a free function — declared outside the class, taking both sides of << as explicit parameters. First parameter is the stream (by reference — streams cannot be copied), second is the object to print (by const reference — printing does not need to modify it and should not copy it). Return type std::ostream&, returning os, is what makes chained output like std::cout << "a: " << a << std::endl; work — each << call needs to hand back a stream for the next << to act on.
Contrast: this is a different operator<< from bigint's digit-shift bigint's subject requires operator<< to also mean "shift digits": 42 << 3 == 42000. That is a completely separate overload — different parameter types (bigint << int, both are bigint/int, not ostream/bigint), so the compiler picks between them purely by matching parameter types, same as any other overloaded function name. << the symbol carries no fixed meaning by itself; each overload you declare gives it one meaning for one specific pair of operand types.

What you write

In vect2/vect2.hpp, outside the class vect2 { ... }; block: declare the free function above. In vect2/vect2.cpp: implement it using operator[] from lesson 2 to read the two components. Match the required format exactly: std::cout << v must print the same characters as std::cout << "{" << v[0] << ", " << v[1] << "}" (subject's own equivalence check).
