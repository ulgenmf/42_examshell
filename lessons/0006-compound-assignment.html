Compound assignment: +=, -=, *= Cluster: modify-in-place operators — 1 rule, and the rule that makes chaining work

Source: vect2 main — v2 += v3;, v1 -= v2;, v1 *= 42;, and the chained form v2 += v2 += v3;. bigint main has c += a, d <<= 4, d >>= (const bigint)2 — same rule, different operator tokens.

Difference from lesson 4's operator+

operator+ (lesson 4) produces a new object and leaves both operands unchanged. operator+= modifies the left operand in place and produces no new object — it hands back the same object it just modified, so the expression itself still has a value to use.

Slot: declaration, inside the class, returns a reference vect2& operator+=(const vect2& other); Rule: return type is vect2& — a reference to the object itself (return *this; — this is a pointer to the current object, *this is that object). No trailing const: this function changes the object's own components, so it cannot be called on a const object. Same shape for operator-= and operator*= (the right-hand parameter of *= is int, not vect2).
Contrast: why v2 += v2 += v3 only works because of the reference return Evaluated right to left: v2 += v3 runs first, modifies v2, and returns a reference to v2 itself (not a copy). The outer v2 += (that reference) then reads v2's new value and adds it again. If operator+= returned vect2 by value instead of vect2&, the chained line would still compile (a copy is still usable in the same way) but would be doing needless extra copying — for these exercises the reference return is what the subject's expected output depends on for d <<= 4 style chained/nested usage in bigint.

What you write

Add operator+=, operator-=, operator*=(int) to vect2.hpp/.cpp. Recompile through v2 += v3;, v1 -= v2;, v2 += v2 += v3;, v1 *= 42;.
