Constructing a vect2 Cluster: how an object comes into existence — 4 related forms, 1 mechanism

Source: vect2/main.cpp, lines 6–9 (from test/subs.txt). These four lines all do the same kind of thing — make a vect2 object exist — but each hits a different slot in the grammar. Same underlying mechanism, different rule per slot. 

vect2 v1;            // line A
vect2 v2(1, 2);       // line B
const vect2 v3(v2);   // line C
vect2 v4 = v2;        // line D

The mechanism: constructor

A constructor is a function with the same name as the class, no return type, that runs exactly once — at the moment an object is created. Every line above triggers some constructor. Which one, and with what syntax, is what differs.

Slot A — default construction

Slot: Type name; vect2 v1; — no parentheses, no arguments.
Rule: this calls the default constructor — the constructor that takes zero arguments. If you write no constructors at all, the compiler generates one for you automatically. If you write any constructor yourself, the compiler stops generating this one — you must write it yourself if you still want vect2 v1; to compile.

Slot B — parameterised, direct-initialization

Slot: Type name(args); vect2 v2(1, 2); Rule: this calls whichever constructor's parameter list matches (1, 2) — here, a constructor taking two ints. This syntax is called direct-initialization.
Named collision (per this repo's teaching rule) Type name(args) in a declaration slot (a type name immediately to the left) is construction. existing.method(args) in an invocation slot (a variable name, already existing, to the left of the dot) is a method call. Same parenthesis shape, unrelated rule — the thing that disambiguates them is what sits immediately to the left: a type, or an existing object.

Slot C — copy construction, direct-init, plus const

Slot: const Type name(existing); const vect2 v3(v2); Rule: passing an existing vect2 (v2) as the sole argument selects the copy constructor — a constructor whose job is to duplicate an existing object's state into the new one. This is still direct-initialization syntax (parentheses), same slot as B, but the argument type changes which overload of the constructor gets picked.

const here sits in the declaration slot, to the left of the variable name: it means v3 itself cannot be reassigned or have its non-const members changed after construction. (There are two other slots const can occupy in this codebase's exercises — deferred to a later lesson, noted in the glossary as a term to revisit.)

Slot D — copy construction, copy-initialization

Slot: Type name = existing; vect2 v4 = v2; Rule: despite the =, this is not assignment — there is no v4 yet for anything to be assigned into. This is copy-initialization: the compiler sees a brand-new variable being declared with an initial value, and calls the same copy constructor as slot C. Different syntax, same constructor as C — that's the collision worth holding onto: Type x(y) and Type x = y are two slots that can both resolve to the copy constructor.
Named collision: this = vs. real assignment vect2 v4 = v2; (declaration, = in the initializer position) calls the copy constructor. v4 = v2; on its own line, where v4 already exists, would call operator= — the copy assignment operator — a completely different function. Same = symbol, resolved by whether the left side is being declared right now or already exists. (Full rule on operator= — separate lesson, once we reach polyset's orthodox canonical form requirement.)
