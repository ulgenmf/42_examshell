Comparison: ==, !=, and ordering Cluster: operators returning bool — vect2 needs 2 of them, bigint needs all 6

Source: vect2 main — v1 == v3, v1 == v1, v1 != v3, v1 != v1. bigint main additionally needs d < a, d <= a, d > a, d >= a.

Slot: declaration, inside the class, returns bool bool operator==(const vect2& other) const; Rule: same member-function shape as lesson 4's operator+ — left operand implicit, right operand explicit parameter — but the return type is bool, not vect2. const on the function: neither side is modified by a comparison.
Contrast: != is not automatically derived from == In C++ (before C++20), writing operator== does not give you operator!= for free — they are two separate overloads you must declare and define individually, even though != is logically just !(a == b). The usual pattern is to define operator== with the real comparison logic, then define operator!= as return !(*this == other); to avoid repeating the logic.

For bigint's <, <=, >, >=: same slot and rule as ==, four separate overloads, each returning bool. Same non-derivation problem applies — none of the six comparison operators are generated from another automatically in this language standard.

What you write (vect2 only, for now)

Add operator== and operator!= to vect2.hpp/.cpp. Recompile through the four comparison lines at the end of vect2/main.cpp. This completes everything vect2's main.cpp needs — full recompile and check every printed line against its comment.
