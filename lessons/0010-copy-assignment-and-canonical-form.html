operator=, and the required four-function set Cluster: what makes a class fully copyable and destructible — required by polyset's subject text directly

Not exercised by vect2's main.cpp directly (the compiler-generated version already works for vect2 since it has no pointer members), but polyset's subject states explicitly: "All classes should be under orthodox canonical form." This lesson defines that term precisely — it is 42-specific terminology, not standard C++ wording, so no external source names it exactly this way.

The four functions

A class in orthodox canonical form declares all four of the following, even if some bodies are trivial:

1. Default constructor vect2(); — covered in lesson 1.
2. Copy constructor vect2(const vect2& other); — covered in lesson 1. Constructs a new object from an existing one.
3. Copy assignment operator vect2& operator=(const vect2& other); Rule: called when an already-existing object is assigned a new value: existing = other; (contrast with lesson 1's copy-initialization, Type x = y;, which is construction, not this). Copies each member from other into *this, then returns *this by reference — same reference-return reasoning as lesson 6, needed so a = b = c; chains correctly.
4. Destructor ~vect2(); Rule: class name preceded by ~, no parameters, no return type. Runs automatically when the object's lifetime ends (goes out of scope, or is deleted if heap-allocated). For a class with no pointer members, the compiler-generated destructor is already correct and an empty body ~vect2() {} is enough to declare — the requirement is that it exists explicitly, not that it does unusual work.
Why this matters more for bigint/polyset than vect2 vect2 stores two plain ints — the compiler-generated versions of all four functions already do the right thing (copy each int, nothing to release on destruction). Once a class stores a pointer to owned memory (a dynamically-sized digit array for bigint, for example) or is used as a base class (polyset), the compiler-generated versions become wrong or unsafe, and writing all four yourself stops being optional. Deferred: the specific pointer-ownership rule, until bigint.

What you write

Add an explicit default constructor (if not already present as a separate function from the copy constructor), copy constructor, operator=, and destructor to vect2.hpp/.cpp, even though vect2 does not strictly need them yet — this is the pattern that must be reflexive before bigint and polyset, where it stops being optional.
